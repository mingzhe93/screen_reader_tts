VoiceReader files bundled with the app (src-tauri/binaries)

What belongs here depends on the build and platform. This file, the Windows SoX
files in sox/, and the small Metal decoder graphs/notices in audio8-metal/ are
repository assets. Models, ONNX Runtime, Kyutai clips, macOS SoX and sidecar folders
are generated/downloaded and git-ignored.

Folders
-------
models/Verylicious/pocket-tts-ungated/   Both builds. Kyutai Pocket TTS model.
  Generated by the model-bundling step (copied from tts-engine/.data/models; if
  missing, tts-engine/scripts/prefetch_models.py downloads it from Hugging Face).
  The helper prefers tts-engine/.venv Python when available. Not committed.
  The app treats the folder as valid only if it contains:
    voicereader-pocket-tts.yaml
    tts_b6369a24.safetensors
    tokenizer.model
    embeddings/alba.safetensors
  The folder also holds the other seven built-in preset voices under embeddings/.

sox/   Windows SoX executable, DLLs and licence files. Committed.
  Used for normalizing voice-cloning clips, the optional legacy Base speed path
  (VOICEREADER_RATE_IN_BACKEND=1), and Full-build sidecar speed changes. Default
  Base playback uses the player's WSOLA stretcher and does not require SoX.
  On Windows, the model/sidecar build helper copies the runtime and notices from
  VOICEREADER_SOX_PATH, PATH or winget. If none is found, it warns and leaves the
  existing folder alone. Legacy Base speed processing without SoX resamples and
  changes pitch; the Full sidecar also tries librosa before resampling.

sox-macos/   Native macOS SoX with static libsox and only OS dylib dependencies.
  Built by scripts/bundle_sox_macos.py during the model/sidecar bundling step.
  Required for the macOS portable Base build; a failed build stops packaging.
  The source is checksum-verified and cached under build/sox-macos. The bundle
  includes licences, corresponding source, the patched header and build recipe.
  It supports raw PCM, WAV and tempo effects, with external codecs/device drivers
  disabled. Targets macOS 14+. Not committed. Building on macOS preserves sox/;
  the Windows executables are excluded by the dedicated macOS Base configs.

onnxruntime/   Base build. Shared library used by Audio8 TTS and transcription.
  Fetched by npm run onnxruntime:fetch (scripts/fetch-onnxruntime.js).
  Not committed. VERSION.txt records the core version (1.24.4, or 1.23.2 for
  Intel macOS; Windows also uses DirectML 1.15.4). Contents by platform:
    Windows: onnxruntime.dll (DirectML build) and DirectML.dll (x64 and ARM64)
    macOS:   libonnxruntime.dylib (Apple Silicon or Intel)
    Linux:   libonnxruntime.so (x64)
  Loaded by path, never from the system library path. Set
  VOICEREADER_ONNXRUNTIME_PATH to use a different core library.
  Apple Silicon Base builds also fetch WebGPU plugin 0.4.0 with
  scripts/fetch-webgpu-macos.js, requiring pinned core 1.24.4. It adds:
    libonnxruntime_providers_webgpu.dylib
    WEBGPU_VERSION.json, WEBGPU_README.md, webgpu-licenses/
  The archive checksum is verified. The plugin loads lazily beside the core
  library and uses Dawn/Metal in the Rust process; no Python runtime is needed.
  npm run assets:fetch fetches the core runtime, the Metal plugin on Apple
  Silicon, and Kyutai clips. The plugin step skips other platforms.

audio8-metal/   Apple Silicon macOS Base builds. Small, reproducible graph assets:
    codec_decoder_fp32.onnx, codec_decoder_fp16.source.onnx
    LICENSE, NOTICE, README.txt
  The derived graph computes in FP32, reusing the existing downloaded FP16 weight
  file. The original graph is included to validate the exact supported export.
  At run time, the app verifies the installed original and caches the derived
  graph next to the weights as codec_decoder_webgpu_fp32_v1.onnx. CPU uses the
  original graph. A mismatch or preparation/load failure falls back to CPU.
  Regenerate with scripts/prepare_audio8_metal_decoder.py (build-only numpy/onnx).
  See docs/METAL.md and docs/learnings.md section 15 for validation.

kyutai-voices/   Base build. Reference clips for the 13 extra Kyutai presets,
  plus ATTRIBUTION.txt. Fetched by npm run kyutai-voices:fetch
  (scripts/fetch-kyutai-voices.js). Not committed. Without it, only the eight
  built-in presets work.

tts-engine-<target triple>/   Full build. Python sidecar, built by
  npm run sidecar:build (PyInstaller, one folder; .build-profile marks the build).
  Not committed.
    Windows:      tts-engine-x86_64-pc-windows-msvc/tts-engine.exe
    macOS Intel:  tts-engine-x86_64-apple-darwin/tts-engine
    macOS Arm:    tts-engine-aarch64-apple-darwin/tts-engine
    Linux x86_64: tts-engine-x86_64-unknown-linux-gnu/tts-engine
  npm run sidecar:build also bundles the Kyutai model and platform SoX. The Full
  Python service currently searches bundled sox/ paths, not sox-macos/; set
  VOICEREADER_SOX_PATH to the native executable when testing Full on macOS.

The Audio8 model (about 860 MB) and transcription models (Parakeet plus the
Nemotron-3 diarizer, about 1.07 GB together) are not bundled. The app downloads
them into the data directory under models/. Metal reuses that download.

What each build bundles
-----------------------
Windows Base: tauri.base.conf.json selects models/, sox/, onnxruntime/ and
  kyutai-voices/. No sidecar.
macOS Base: tauri.macos.conf.json selects models/, sox-macos/, onnxruntime/ and
  kyutai-voices/ plus audio8-metal/, with the macOS icon and minimum OS 14.0.
  Apple Silicon includes the WebGPU plugin; Intel stays on CPU. No Windows SoX.
Full: tauri.conf.json selects binaries/**/*, including the sidecar folder;
  beforeBuildCommand runs npm run sidecar:build && npm run build.

Portable packages (scripts/package_portable.py):
  Windows Base: copies models/ (required), onnxruntime/, kyutai-voices/ and sox/
    next to the executable. Missing optional folders warn rather than fail.
  Windows Full: copies the complete binaries/ tree next to the executable.
  macOS Base: packages the assembled .app with ditto to preserve bundle metadata,
    permissions and symlinks. Checks required assets and matching app/runtime
    architectures. Full portable packaging on macOS is not supported.
  macOS Apple Silicon: additionally requires an arm64 WebGPU plugin and the
    decoder graphs/licences. All Mac packages ad hoc sign and verify the complete
    app before creating the ZIP. See docs/RELEASING.md.

Commands
--------
Full sidecar build:                npm run sidecar:build
Bundle Kyutai model/platform SoX:  npm run models:bundle:kyutai
Rebuild native Mac SoX:            python3 scripts/bundle_sox_macos.py
Fetch core ONNX Runtime:           npm run onnxruntime:fetch
Fetch extra Kyutai voice clips:    npm run kyutai-voices:fetch
Fetch core/Metal/voice assets:     npm run assets:fetch
Fetch native Mac Metal plugin:    node scripts/fetch-webgpu-macos.js
Windows Base installer:           npm run desktop:build:base:installer
Windows Base portable:            npm run desktop:build:base:portable
Windows Full portable:            npm run desktop:build:full:portable
macOS Base portable:              npm run desktop:build:macos:portable
